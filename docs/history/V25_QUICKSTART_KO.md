# 포커칩 v2.5 — 오늘 실험에 사용하는 순서

## 설치와 실행

ZIP을 새 폴더에 풀고 안쪽 **pokerchip_research** 폴더를 여세요. v2 폴더에 덮어쓰지 않습니다.

1. 처음 한 번 `SETUP.cmd`를 실행합니다. 인터넷으로 필요한 라이브러리를 설치합니다.
2. 이후에는 `RUN.cmd`만 실행합니다.
3. Python 3.14를 그대로 사용할 수 있습니다. 검증 환경은 Windows Python 3.14.6입니다. 별도 EXE는 아닙니다.

기존 v1 가상환경을 이용하려면, VS Code에서 v2.5 폴더를 연 뒤 기존 가상환경의 Python으로 `run_gui.py`를 실행해도 됩니다. 새 설치를 선택한다면 다음 순서입니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe run_gui.py
```

## 촬영 전에 확인할 것

- **검정 칩**에 **가장자리 한 곳만 색 표시**하고 가운데에 스티커를 붙입니다. 칩 전체가 컬러인 방식은 사용하지 않습니다. 색 조합을 빨강/파랑 등으로 강제하지 않으며, 기본 자동 모드는 채도가 있는 가장자리 표시로 회전각을 계산합니다.
- **가운데 스티커가 정확히 중심에 있어도 됩니다.** 중심 스티커 자체는 회전각을 알려주지 못하므로, 회전 방향은 가장자리 색 표시에서 얻습니다. 흰색/검정색처럼 채도가 없는 표시나 너무 작은 표시는 회전 자동 검출이 어려울 수 있습니다.
- 기본 질량 **12 g**, 지름 **40 mm**입니다. 첫 화면에서 바꿀 수 있습니다. 관성은 균질 원판 `I=½mR²` 근사이며 실측을 대신하지 않습니다. 두께와 개별 관성은 세부 설정에서 입력할 수 있습니다.
- 바닥 바둑판 한 칸은 **42.9/18 cm = 23.833333… mm**입니다. **보정판 한 칸 15 mm와 다릅니다.** 둘은 분리 저장됩니다.
- 기본 영상은 **FHD, 파일 재생 30 fps, 원래 촬영 240 fps, 전체 1/8배속**입니다. 실제 시간은 파일 재생시간의 1/8입니다. 예전 60fps 일반 속도 영상을 분석할 때는 첫 화면에서 영상 종류를 바꾸세요. 한 프로젝트에 서로 다른 시간 조건을 섞기보다 프로젝트를 나누는 편이 간단합니다.
- 가능하면 시작 전에 모든 칩을 겹치지 않게 보여주는 구간을 남기세요. 가려진 채 출발한 칩은 자동 개수에서 빠질 수 있습니다. 이는 화면에 보이지 않는 물체를 확정할 수 없는 한계입니다.
- 초점·줌·해상도·카메라 위치를 보정 이후 유지하세요. 밝은 조명과 짧은 노출이 빠른 회전의 흐림을 줄입니다. 롤링셔터 보정은 사용하지 않습니다.

## 보정 영상 촬영 방법

첨부 PDF 규격을 고정 입력했습니다.

| 항목 | 값 |
|---|---|
| PDF 용지 크기 | 200 × 150 mm |
| 보정판 배열 | 가로 11칸 × 세로 8칸 |
| 정사각형 한 변 | 15 mm |
| 마커 한 변 | 11 mm |
| 마커 | 4×4 패턴, ID 0~43; OpenCV DICT_4X4_50과 일치 |
| 보드 패턴 | OpenCV legacy_pattern=False |

`resources/calibration_board.pdf`도 넣었습니다. **인쇄할 때 100% / 실제 크기**로 출력하세요. ‘용지에 맞춤’으로 줄이면 길이와 속도가 함께 틀어집니다. 자로 인쇄된 한 칸이 15 mm인지 확인하세요.

한 영상 안에서 다음과 같이 촬영하면 됩니다.

1. 여러 위치·기울기로 판을 보여줍니다. 이 구간은 렌즈 왜곡 추정용입니다.
2. **마지막에는 판을 실제 실험 바닥에 평평하게 놓고**, 카메라를 고정한 상태에서 충분히 멈춰 촬영합니다. 최소 재생시간 2초 정도를 권장하며 더 길어도 됩니다.
3. 판을 치운 후 **카메라를 건드리지 않고** 실험합니다. 디지털 줌·초점 모드도 유지하세요.

프로그램은 마지막 정지 구간의 판으로 바닥의 거리 변환을 구합니다. 기울인 판의 영상이 충분하지 않으면 렌즈 보정은 적용하지 않고 평면 보정만 사용합니다. 판을 손에 든 장면만으로는 바닥 평면을 확정하지 않습니다.

바닥의 격자선이 충분히 보이면 23.8333 mm 간격과 대략 맞는지도 검사합니다. 두 선 방향에서 신뢰할 만한 간격을 찾지 못하면 검사 불가로 남깁니다. 8% 이상 큰 불일치가 확인되면 해당 영상의 m 단위 계산을 막습니다. **8%는 큰 설정 오류를 찾는 기준이지 허용 측정 정확도가 아닙니다.**

## 분석: 첫 화면에서 끝내기

1. **보정 영상 선택** 또는 첫 상자에 영상 드래그.
2. 결과를 저장할 빈 폴더를 선택합니다. 다음 실행에서 이 폴더의 `project.json`을 열면 설정을 다시 쓸 수 있습니다.
3. 마지막에 판을 바닥에 놓았고 카메라를 움직이지 않았다면 해당 확인란을 체크합니다.
4. **실험 영상 추가** 또는 두 번째 상자에 영상을 여러 개 드래그.
5. 기본 질량·지름·영상 종류를 확인하고 **분석 시작 · 데이터 자동 저장**을 누릅니다.

이후 보정 → 개수 제안 → 중심·회전 추적 → 속도 계산 → 파일 저장까지 진행합니다. 일부 영상에 문제가 생겨도 다음 영상을 계속 처리합니다. 중단하면 이미 완료된 영상의 결과를 저장합니다.

보정이 실패해도 픽셀 좌표는 분석할 수 있습니다. 시간 조건이 있으면 px/s 단위 속도도 저장합니다. **m 단위 값이 빈칸인 것을 0으로 해석하지 마세요.** 위치 자체를 한 번도 찾지 못한 영상은 성공으로 표시하지 않습니다.

## 결과가 제대로 나왔는지 확인

**저장된 결과** 화면에서 영상마다 확인합니다.

- **파일 저장**: 처리·저장이 완료됐는지, 실패했는지.
- **거리·속도**: 실제 거리 계산 가능 / 인쇄 규격에 따른 잠정 계산 / 픽셀 좌표만 가능.
- **회전**: 각속도가 계산된 행 수. 0행이면 표식·흐림·각속도 가정을 확인하세요.
- **확인할 프레임**: 원이 불안정하거나 누락, 번호가 불확실한 프레임 수.
- **칩 수**: 자동으로 제안한 수. 항상 실제 개수와 같다고 보장하지 않습니다.

색상은 초록(완료), 노랑(잠정·확인 필요), 빨강(실패)으로 구분합니다. ‘자동 제안’은 노랑으로 표시합니다. **처리 완료나 기록 비율 100%가 정확도 100%를 뜻하지 않습니다.**

칩 수가 이상하면 `영상 넣기`에서 해당 행을 선택하고 **칩 개수 확인 사진**을 보세요. **선택 영상의 칩 수 수정**으로 1~32개를 직접 지정하고 재분석할 수 있습니다. 0은 자동 인식입니다. 많은 칩·심한 가림에 대한 실물 성능은 검증하지 않았습니다.

영상 행을 두 번 클릭하면 검토 화면이 열립니다.

- **다음 문제 / 이전 문제**: 의심되는 프레임으로 이동.
- 아래 슬라이더 또는 화살표 키: 프레임 이동.
- 휠: 확대, 가운데 버튼 드래그: 이동, 더블클릭: 화면에 맞추기.
- 칩 번호와 **중심 보정 클릭** 선택 → 실제 중심 클릭 → 수정 이유 입력.
- **보정 반영 재분석**: 수정 내용을 새 결과에 반영. 기존 분석 기록은 남깁니다.

가림 후 번호가 확실하지 않으면 억지로 이어 붙이지 않습니다. `unknown_...`은 어느 칩인지 다시 확인해야 한다는 뜻입니다. `chip_1` 등은 **그 영상 안에서 붙인 번호**이며 다른 영상에서도 같은 실물 칩이라는 뜻은 아닙니다.

## 자동 저장 파일

선택한 실험 폴더 안의 `results`를 여세요.

| 파일 | 용도 |
|---|---|
| 전체_운동데이터.csv | 완료된 모든 영상의 위치·속도·회전 데이터를 한 파일로 |
| 영상별_요약.xlsx / csv | 영상별 상태·칩 수·결과 위치 |
| 영상별 폴더의 운동데이터.csv | 해당 영상의 한국어 열 이름 데이터 |
| trajectories.png | 위치·회전·속도 그래프 |
| 확인할_프레임.csv | 직접 확인할 프레임과 이유 |
| 칩개수_확인.jpg | 자동 개수 인식에 사용한 대표 사진 |
| observations.csv / trajectories.csv / events.csv | 기존 분석 호환용 상세 데이터 |
| quality.json / provenance.json | 품질·원본·설정·분석 기록 연결 |

CSV는 Excel에서 한글이 보이도록 UTF-8 BOM으로 저장합니다. 긴 전체 데이터는 CSV로 제공하고, Excel 파일에는 요약을 넣어 행 수 제한을 피합니다.

## 선택 기능: 물리계수와 정확도 검사

기본 흐름에는 피팅 자료 분할이나 수작업 위치 입력을 요구하지 않습니다.

- **세부 설정·물리 피팅 보기**를 켜면 Farkas/IFR 계수 계산과 비교 기능이 나타납니다. 미검증 시간·거리와 미확인 충돌을 자동으로 연구용 계수로 확정하지 않습니다. 정밀 검증/피팅 절차는 기존 `V2_MODEL_AUDIT_KO.md`와 `V2_QUICKSTART_KO.md`의 피팅 부분을 참고하세요.
- **자동 측정의 오차를 직접 비교하기**는 원본을 보고 중심을 직접 표시한 뒤 자동 중심과 차이를 계산하는 선택 도구입니다. 예전 ‘독립 정답 라벨 입력’의 이름을 바꿨으며 일상적인 분석에는 필수가 아닙니다.
- 각속도는 기본 최대 회전 가정 **500 rad/s (약 80회/초)**에 조건부입니다. 실제로 그보다 빠른 회전이나 프레임 사이 한 바퀴 추가 회전은 영상만으로 판별하지 못할 수 있습니다. 속도 상한은 세부 설정에서 바꿀 수 있고, 기본 화면에서 회전 계산을 끌 수도 있습니다.

다수 칩의 궤적은 처리하지만, 동시에 여러 칩이 접촉하는 충돌을 고립된 2체 IFR 충돌처럼 계산하지 않습니다. 자동 예제와 테스트는 실제 스마트폰 실험의 정확도를 보증하지 않습니다.
