# PokerChip Research v2 — 직접 따라 하는 실행 안내

## 1. 설치와 실행

ZIP을 새 폴더에 압축 해제하고 **pokerchip_research 폴더 자체**를 VS Code에서 여세요. `run_gui.py`, `requirements-lock.txt`, `pyproject.toml`이 바로 보여야 합니다. 기존 v1 폴더에 덮어쓰지 마세요.

Python 3.14를 그대로 사용해도 됩니다. 이 배포본은 Windows Python 3.14.6에서 검사했습니다. 새 환경 설치가 필요하면 폴더의 `SETUP.cmd`를 두 번 클릭합니다. 설치 후에는 `RUN.cmd`를 실행합니다.

VS Code의 PowerShell 터미널에서 직접 설치하려면:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe run_gui.py
```

소스 경로를 실행 파일에서 설정하므로 editable 설치는 필수가 아닙니다. 가상환경 활성화도 필요하지 않습니다. 이미 설치가 끝난 v1 가상환경을 쓸 경우 해당 `python.exe`의 경로로 새 v2의 `run_gui.py`를 실행할 수도 있습니다.

## 2. 먼저 합성 데모로 둘러보기

1. 상단 **합성 데모 만들기**를 누르고 새 빈 폴더를 선택합니다.
2. 왼쪽 **2 영상 분석** → **모두 분석 / 재개**를 누릅니다.
3. 작업이 끝나면 **연구 대시보드**에서 관측 비율과 검토 프레임 수를 확인합니다.
4. 영상 행을 두 번 클릭하면 **3 관측·충돌 검토**로 이동합니다.
5. 슬라이더 또는 ←/→ 키로 이동합니다. 마우스 휠로 확대하고, 가운데 버튼으로 이동합니다. 더블클릭하면 전체 화면 크기로 돌아갑니다.
6. `N/P` 또는 **다음/이전 문제**로 검토할 프레임을 순회합니다.
7. 중심 보정은 칩 선택 → **중심 보정 클릭** → 원본 중심 클릭 → 수정 이유 입력 순서입니다.
8. **보정 반영 재분석**을 눌러 새 결과를 만듭니다. 예전 run은 보존됩니다.

합성 데모는 화면과 관측 절차를 확인하는 자료입니다. 궤적 자체가 Farkas 방정식의 해라는 뜻은 아닙니다. 별도의 `fit_dataset.synthetic.json`은 독립 해석식/충격량으로 만든 계수 복원 검사용 데이터입니다.

## 3. 실제 실험 조건 — 이번 연구에서 고정한 내용

- **검정 포커칩만 사용합니다.** 칩 전체가 빨강/초록 등인 컬러 칩은 지원 대상이 아닙니다.
- 가장자리 한 곳에 색칠하고 내부에 작은 스티커를 붙입니다.
- 표식 색 조합은 chip_1: 가장자리 빨강/내부 파랑, chip_2: 파랑/노랑, chip_3: 초록/빨강입니다. v1의 고정 조합을 유지했습니다.
- 1~3칩의 자유운동 및 시간상 분리된 고립 2체 충돌을 지원합니다. 3체 동시접촉·칩 들림·쌓임은 지원되지 않는 사건으로 분류합니다.
- 삼성 FHD 240 fps, 전체 1/8배속에서는 **실제 1초가 재생 8초**입니다.
- 새 프로젝트의 기본 배율은 8입니다. `실제 시간 = PTS 재생시간 / 8`. 240으로 다시 나누지 않습니다.
- 240개 원본 프레임을 30 fps로 재생하는 파일이라면 각 프레임의 실제 간격은 1/240초입니다.
- 이미 240 fps 원래 시간으로 저장된 영상은 배율 1이 필요합니다. 일부만 느려지는 편집본은 고급 시간 구간 설정을 사용합니다.
- v1 프로젝트를 열 때는 기존 시간 설정을 그대로 보존합니다. 과거 60 fps 영상에 배율 8을 자동으로 적용하지 않습니다.

## 4. 실제 영상 분석 순서

### ① 새 프로젝트

프로그램 폴더와 별개인 빈 데이터 폴더를 선택합니다. 원본 영상은 외부 경로로 등록되며 변경되지 않습니다. 다른 PC로 옮긴 경우 **원본 재연결**이 SHA-256을 확인합니다.

### ② 촬영·보정 설정

**촬영 시간**에서 배율 8, 촬영 fps 240을 확인합니다. `촬영 조건 저장`은 잠정 물리시간을 계산할 수 있게 합니다. 독립 시계로 검증하지 않은 시간은 `declared` 상태이고 피팅에는 들어가지 않습니다. 독립 시계 영상에서 재생시각과 타이머를 3개 이상 읽어 **독립 시계 대응점으로 검증**에 입력하세요. 프로그램이 주어진 변환의 시간 오차를 검사합니다. 시계 자체의 정확성과 중복/보간 프레임 여부까지 자동으로 증명하지는 않습니다.

노출시간은 **실제 ms** 단위입니다. 알고 있을 때만 입력하세요. `start/midpoint/end`는 PTS가 노출의 어느 지점을 가리키는지 뜻합니다. rolling-shutter readout을 입력하면 영향 상한을 계산하지만 영상의 행별 왜곡을 자동으로 보정하지는 않습니다.

**카메라·거리**에서 ChArUco 보정 영상을 선택하고 보드의 실측 크기와 마커 사전을 입력합니다. 이어 **평면 대응점·독립 검증점**에서 다음을 입력합니다.

| 열 | 의미 |
|---|---|
| pixel x/y | 원본 영상 좌표. y 아래쪽 |
| 실제 x/y mm | 바닥 실측 좌표. y 위쪽 |
| fit | 변환을 맞출 점. 비공선 4개 이상 |
| holdout | 변환에 사용하지 않은 별도 검증점 |

기본 holdout 허용 RMSE는 0.5 mm이며 연구 허용오차에 맞게 변경할 수 있습니다. 값이 기준을 초과하면 근거 문구가 있어도 `verified`가 되지 않습니다. 렌즈 정보가 없으면 평면 보정은 할 수 있지만 렌즈 왜곡은 미측정 상태입니다.

**칩·계측**에서 질량 g, 반지름 mm, 두께 mm를 입력합니다. 관성모멘트를 실측했으면 kg·m²로 입력하고, 아니라면 `I=½mR²` 근사를 명시적으로 선택합니다. 영상 반지름 탐색 범위를 너무 넓게 잡지 마세요. 원본에서 대략 몇 픽셀인지 확인합니다. 각속도 안전 상한이 비어 있으면 alias 문제 때문에 각속도가 차단됩니다. 자유운동 파일럿으로 합리적인 상한을 정해야 합니다.

**이론 계수**는 직접 값을 넣어 시뮬레이션하거나, 피팅 이후 결과를 적용하는 곳입니다. 모르는 값은 비워두세요.

### ③ 영상 등록·분석

영상 여러 개를 드래그앤드롭하고 칩 수를 정합니다. 촬영 세션, 프레임 구간, 조건은 **선택 조건 수정**에서 설정합니다. 자료가 준비되지 않아도 원 검출부터 시험할 수 있습니다. 거리 보정이 없으면 m 단위 물리량을, 검증된 시간이 없으면 계수 피팅을 확정하지 않습니다.

### ④ 관측·표식·사건 검토

영상 행을 두 번 클릭합니다. **표식 학습·ID·각도 도구**를 펼치고, 같은 프레임에서 rim/inner를 각각 클릭한 후 표식 학습을 저장합니다. `rim`은 가장자리 색칠, `inner`는 내부 스티커입니다. 모호한 unknown ID는 고급 ID 도구에서 고유 ID로 지정할 수 있습니다.

중심이 아예 누락되었으면 해당 chip ID를 선택한 뒤 중심 보정 모드로 클릭하여 반지름과 근거를 입력합니다. 생성한 수동 관측은 자동 검출 성능 평가에 포함하지 않습니다. 각도는 자동으로 채워지지 않으며 원본에서 확인해야 합니다.

충돌 후보를 확인하고 고립 2체 충돌만 승인합니다. 승인 후 **보정 반영 재분석**을 실행해야 피팅 입력이 갱신됩니다. 다중접촉·불확실한 접촉은 제외 사유를 남깁니다.

### ⑤ 피팅·검증

검토한 run을 선택한 상태에서 **현재 run → 피팅 데이터 추가**를 누릅니다. 충돌이 없는 연속 자유운동 구간 또는 승인한 고립 충돌을 추가합니다. **학습/보류/최종시험 세션 지정**에서 전체 촬영 세션 단위로 나눕니다.

- 학습: 계수 추정
- 보류: 모델 선택과 예측오차 평가
- 잠긴 최종시험: 피팅과 모델선택에 섞지 않을 자료

먼저 bootstrap 0으로 점추정을 확인하세요. CI를 얻으려면 독립 세션을 여러 개 모은 뒤 bootstrap 횟수를 늘립니다. 200회는 출발점일 뿐이며 반복수·세션수에 따른 안정성을 확인해야 합니다. 세션이 하나뿐이면 전체 세션 bootstrap CI는 계산하지 않습니다.

계수 표에는 추정값, CI, 물리 허용성, 식별성이 함께 나타납니다. 아래 표에는 보류 실험의 RMSE/MAE가 표시됩니다. `95% 관측오차 내 비율`은 입력 관측 sigma에 대한 조건부 비율로, 완전한 예측구간 coverage가 아닙니다. 접선 민감도 스캔은 다른 계수와 EIV 상태를 다시 최적화하며 robust 목적함수의 평평한 영역을 보여줍니다. 이를 곧바로 카이제곱 신뢰구간으로 해석하지 마세요.

## 5. ‘정확도가 얼마인가’를 확인하는 방법

**관측 비율 100%는 정확도 100%가 아닙니다.** 오검출도 관측 행을 만들 수 있습니다.

검토 화면의 **독립 정답 라벨 입력**에서 자동 원이 없는 원본을 보고 중심·반지름·선택적 각도를 입력합니다. 해당 프레임의 모든 보이는 칩을 입력했을 때만 완전 라벨로 체크합니다. 칩이 없는 프레임도 0개 완전 라벨로 입력할 수 있습니다.

**정답과 자동 결과 비교**를 누르면 recall, precision, 중심 RMSE, 각도 MAE, ID 변화가 저장됩니다. 이 평가는 원시 자동 관측에 대한 것이므로 수동 수정으로 성능을 부풀리지 않습니다. 정답 잠금을 하면 이후 편집이 차단됩니다. 일부 라벨 프레임에서 얻은 결과를 모든 실제 촬영 조건으로 일반화해서는 안 됩니다.

## 6. 저장되는 결과

프로젝트에는 다음이 저장됩니다.

```text
project.json              설정과 실험 목록
project.v1.backup.json    v1을 처음 저장할 때 원본 백업
runs/run_.../             실행별 원본 hash·설정·관측·파생 결과
  records.sqlite          프레임별 관측/예측/수동수정/운동학/사건
  export/quality.json     관측 비율·검토 목록·시간·rolling shutter 평가
  export/label_validation.json  독립 정답 평가 (실행했을 때)
  export/REPORT_KO.md     실행별 한국어 결과 설명
  export/*.csv / *.jsonl / summary.xlsx
fits/                     피팅 데이터·계수·CI·보류 평가
labels/                   독립 정답
cache/                    중단 재개와 단계별 재사용
```

대시보드에 **이전 설정 · 재분석 필요**가 나오면 현재 설정과 결과가 일치하지 않는 것입니다. 원본 run을 덮어쓰지 않고 새 분석을 만드세요.

## 7. 자동검사와 CLI

```powershell
New-Item -ItemType Directory -Force .\work | Out-Null
.\.venv\Scripts\python.exe -m pytest -q --basetemp .\work\pytest-local
.\.venv\Scripts\python.exe run_cli.py --help
.\.venv\Scripts\python.exe run_cli.py quality "프로젝트 폴더"
.\.venv\Scripts\python.exe run_cli.py validate-labels "run 폴더" "labels.json"
```

`--basetemp`에는 이 검사 전용 폴더를 쓰세요. pytest가 다음 실행 시 해당 폴더를 정리합니다.

## 8. 현재 범위

실제 삼성 240 fps 원본·독립 시계·실측 물성·새 표식의 라벨 자료가 아직 충분히 없으므로, 합성 검사 통과를 실제 실험 정확도 보증으로 표시하지 않습니다. 완전한 카메라 파라미터 공분산 전파, 행별 rolling-shutter 영상 보정, 계층 Bayesian 모델, 진짜 동시 다체 충돌은 제공하지 않습니다. 해당 조건은 숨기지 않고 미검증·미지원으로 보고합니다. 자세한 변경과 검증 범위는 `V2_RELEASE_NOTES_KO.md`, `V2_VALIDATION_KO.md`를 확인하세요.
