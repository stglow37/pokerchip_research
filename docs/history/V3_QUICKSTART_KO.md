# v3 따라 하는 사용 설명서

## 설치와 실행

ZIP을 압축 해제한 다음 `pokerchip_research` 폴더 안에서 `SETUP.cmd`를 더블 클릭합니다. 처음에는 필요한 패키지를 내려받으므로 인터넷이 필요합니다. 설치 완료 뒤 `RUN.cmd`를 엽니다. 이후에는 RUN만 실행하면 됩니다. ZIP 미리보기 안에서 실행하지 마세요.

Python 3.14를 그대로 사용할 수 있습니다. 이번 검사는 기존 Windows Python 3.14.6 환경에서 수행했습니다. 3.12를 새로 설치할 필요는 없습니다. 설치 오류가 발생하면 마지막 오류 문장을 확인해야 합니다.

VS Code에서는 **SETUP.cmd가 보이는 폴더 자체**를 열고 터미널에서 실행합니다.

```powershell
.\SETUP.cmd
.\RUN.cmd
```

이미 v1의 가상환경이 설치되어 있다면 새 설치 없이 새 v3 폴더에서 다음과 같이 실행할 수도 있습니다.

```powershell
& 'D:\내 파일\문서\카카오톡 받은 파일\PokerChip_Astra_v1\.venv\Scripts\python.exe' .\run_gui.py
```

위 경로는 이번 컴퓨터의 기존 환경입니다. 다른 컴퓨터에서는 SETUP을 사용하세요. `run_gui.py`는 v3의 src를 먼저 불러옵니다. 기존 v2.5에 덮어쓰지 말고 별도 폴더에 보관하세요.

## 첫 분석

1. **새 실험 폴더 / 저장 위치 선택**에서 비어 있는 새 폴더를 정합니다. 예: `D:\포커칩결과\0928_v3`.
2. **보정 영상**에 ChArUco 영상을 놓습니다. 규격은 11×8칸, 한 칸 15mm, 마커 11mm, DICT_4X4_50으로 고정입니다. 끝부분에 실제 바닥에 평평하게 놓았다면 확인란을 체크합니다. 사실과 다르면 체크하지 않습니다.
3. **실험 영상**에 네 파일을 한꺼번에 놓습니다. 192442, 192447, 200458, 200506의 기대 개수는 1, 1, 2, 2입니다.
4. 기본값을 확인합니다. 질량 12g, 지름 40mm, 긴 격자 23.8889mm, 짧은 격자 22.5mm. 삼성 240→30fps·전체 1/8배속을 유지합니다.
5. **분석 시작 · 데이터 자동 저장**을 누릅니다. 중단 버튼은 현재 작업을 정리하고 멈춥니다.
6. **저장된 결과 → 결과 폴더 열기**를 누릅니다. 원본 MP4는 수정하지 않습니다.

같은 렌즈·줌·초점·해상도 조건이면 저장한 실험 프로젝트에서 보정 정보를 재사용할 수 있습니다. v3는 각 실험 영상의 격자로 바닥 좌표를 다시 구합니다. 카메라 위치가 달라진 영상에 예전 평면 변환을 그대로 복사하지 않습니다. 렌즈 조건이 바뀌면 새 보정 영상이 필요합니다.

## 결과는 이 순서로 확인

`영상별_요약.xlsx`에서 처리 상태, 관측 비율, 회전 계산 행 수, 확인 프레임 수를 봅니다. 영상별 하위 폴더에는 다음 파일이 있습니다.

| 파일 | 용도 |
|---|---|
| `검출_확인.jpg` | 초기·중간·끝·충돌 부근의 실제 검출 원과 칩 번호. 손이나 발사 장치를 잡았는지 먼저 확인 |
| `칩개수_확인.jpg` | 자동 개수 제안의 근거 사진 |
| `운동데이터.csv` | 한국어 열 이름의 시간, 위치, 속도, 각도, 각속도, 상태 |
| `trajectories.png` | 운동 그래프 |
| `확인할_프레임.csv` | 의심 프레임 목록 |
| `review_intervals.csv` | 같은 이유를 연속 구간으로 묶은 목록 |
| `physics_preview.json` | 조건이 되는 자유운동 구간의 Farkas 탐색 피팅과 충돌 후보 |
| `Farkas_preview_chip_*.png` | 같은 구간에 맞춘 관측·모델 비교 |
| `quality.json` | 관측·누락·검토 대상 등 품질 기록 |
| `provenance.json` | 원본과 분석 기록의 연결 |

전체 데이터는 `전체_운동데이터.csv`에 합쳐집니다. CSV는 Excel에서 열 수 있도록 UTF-8 BOM으로 저장합니다. 과거 분석 기록도 남을 수 있으므로 최신 경로는 요약표를 따릅니다.

## 이상한 부분만 직접 확인

**저장된 결과**에서 영상을 선택하고 **선택 영상의 이상한 부분 확인**을 누릅니다. 원이 실제 테두리에 맞는지, 번호가 바뀌는지, 표식이 맞는지 봅니다. 개수가 틀리면 **영상 넣기 → 선택 영상의 칩 수 수정**에서 고친 뒤 다시 분석합니다. 중심·번호 등의 세부 수정은 검토 화면에서 가능합니다. 수정 뒤 다시 분석해야 속도·충돌 결과도 갱신됩니다.

가림이나 화면 이탈 동안은 값이 비어도 정상입니다. 예측 위치는 관측값으로 저장하지 않습니다. 흐린 프레임은 원이 검출되어도 확인 대상으로 표시합니다. 빈 값은 정지 상태 0과 다릅니다.

## 숫자의 의미

- `provisional`: 격자·보정판 가정에 따라 거리로 바꾼 잠정값. 별도의 자 측정으로 검증된 상태는 아닙니다.
- `declared`: 지정한 전체 1/8배속을 적용한 시간. 파일 timestamp를 8로 나눕니다. 파일 8초는 실제 1초입니다.
- 관측 비율: 전체 프레임×지정 칩 수 대비 관측 행 수. 화면 밖 칩도 분모에 포함합니다. 정확도나 검출 재현율이 아닙니다.
- 위치 적합 RMSE: 피팅 구간에서 모델이 관측에 얼마나 가까운지입니다. 영상 측정 오차·미래 예측 오차·계수 신뢰구간이 아닙니다.
- 검토 대상: 흐림, 가림, 표식 부족, 경계 접근, 충돌 후보 등입니다. 저장 실패라는 뜻은 아닙니다.

## 물리 모델

**선택 영상의 물리 분석 요약**에서 탐색 마찰계수와 충돌 후보를 확인합니다. 자동 자유운동 피팅은 충분한 이동·회전이 있는 연속 구간을 사용합니다. 성공해도 독립 검증이 아닙니다.

**세부 설정·물리 피팅 보기**를 켜면 기존 Farkas, IFR, 연속 시뮬레이션, 피팅·비교 기능에 접근합니다. 공식 피팅에는 확인된 시간·기하 정보와 검토된 데이터가 필요합니다. 무리하게 ‘검증됨’으로 바꿔 통과시키면 안 됩니다. 자동 경로는 불확실한 충돌에 임의의 접선 반발·충돌 마찰계수를 넣지 않습니다.

## 촬영·지원 범위

기본 조합은 칩1 빨강 가장자리/파랑 내부, 칩2 파랑 가장자리/노랑 내부입니다. 몸체는 검정입니다. 중심에 가까운 스티커는 식별용이고 회전각 기준은 가장자리 표시입니다. 내부 각도를 이용하려면 상대 각도 보정이 필요합니다.

실제 검사는 이 두 칩의 1개·2개 영상 네 편입니다. 3개 이상은 설정할 수 있지만 실제 정확도는 미검증입니다. 기본 칩3는 초록/빨강, 이후는 일반 색 표식·위치로 연결합니다. 다른 표식이면 프로젝트의 칩별 rim_color/inner_color와 학습 표식을 맞춰야 합니다. 같은 색 조합의 칩이 가려졌다 다시 나타나면 실물 번호는 구별할 수 없습니다.

자동 격자 보정은 지금처럼 위에서 찍고 두 방향 격자가 충분히 보이는 영상용입니다. 큰 기울기·회전·그림자·격자 가림은 실패 원인입니다. 영상에서 긴 간격에 긴 실제 치수를 배정하는 것은 수직에 가까운 촬영 가정에 조건부입니다. 실패하면 m·m/s를 꾸며내지 않고 픽셀 자료를 남깁니다. 바닥과 칩 윗면의 높이 차이에 따른 잔여 오차도 있습니다.

전체 1/8배속이 아닌 편집 영상, 보간 프레임이 들어간 영상에는 기본 시간 설정을 그대로 쓰면 안 됩니다. 빠른 회전의 alias, 모션 블러, 롤링셔터는 완전히 제거하지 않습니다. 롤링셔터 보정은 요청대로 꺼져 있습니다.
