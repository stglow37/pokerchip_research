# v6 분담 분석·통합 안내

## 분석 시작 전

통합 담당자가 정확한 Git commit, 공통 칩 물성·물리 모델·분석 설정·시간 해석, 영상 배정, 학습/검증 역할을 확정한다. 분석자는 별도 프로젝트 폴더에서 작업한다. `session_id`는 촬영 세션 식별자이며 분석자 ID가 아니다. 같은 촬영의 여러 클립에 서로 다른 세션 ID를 붙여 독립 실험처럼 만들지 않는다.

클립은 `parent_source_id`에 부모 원본 해시를, `parent_frame_interval`에 원본의 양끝 포함 프레임 범위를 기록한다. 같은 부모는 학습/검증 양쪽으로 나누지 않는다. 보정은 영상별로 달라도 되지만 방법·근거·검증 상태를 보존한다. 알려지지 않은 길이/시간 오차를 검증된 0이라고 기록하지 않는다.

## 분석자 제출

GUI 저장 결과의 ‘분담 제출 정보 저장’에서 분석자 ID를 입력한다. CLI는 `python -m pokerchip submission PROJECT --analyst ID`다. 모든 영상의 채택 run과 촬영 `session_id`를 확인한 뒤 project.json, submission.json, 해당 runs의 설정/manifest/experiment/records.sqlite/산출물 및 수정 이력을 함께 제출한다. 세션 ID 누락은 제출·통합 검사에서 차단한다. 계수 파일만 보내서는 관측을 합칠 수 없다. 원본 영상은 해시와 재연결 경로로 관리하고 배포 여부는 별도로 결정한다.

## 통합 담당자의 순서

1. `python -m pokerchip integration-inspect A B` 또는 GUI ‘분담 결과 검사·통합’에서 읽기 전용 검사한다. 원본 폴더를 수정하지 않는다.
2. 보고서 entries의 key와 duplicates의 경계/수정 차이를 원본 영상과 대조한다. 같은 원본의 서로 다른 검토본은 한 개를 최종 채택한다. 분석자끼리 좌표나 경계를 평균하지 않는다.
3. 선택 JSON은 원본 SHA 문자열을 채택 key에 대응시킨다. 예: `{"원본SHA":"1:exp_id","__exclude__":["0:other_exp_id"]}`. `__exclude__`는 부모 클립 중복 등의 명시적 제외다. GUI selections에도 같은 객체를 넣는다.
4. `--selections choices.json`으로 재검사한다. 설정 차이는 공통 설정을 적용해 원래 분석자가 새 run을 만든 다음 재제출한다. 미해결 부모 구간/학습·검증 누수는 억지로 승인하지 않는다.
5. `python -m pokerchip integrate NEW_FOLDER A B --selections choices.json`으로 새 통합 프로젝트를 만든다. 기존 폴더는 덮어쓰지 않는다. 관측을 가져오고 통합된 학습 관측으로 계수를 다시 산출한다. 접선 입력 부족 등은 새 결과에 보류 사유로 남는다.
6. 보고서의 채택·제외·원래/새 ID 대응과 계수별 영상/세션 수를 확인한다. 검증 영상은 새 고정계수 검증으로 평가한다. 개발 과정에 사용한 영상은 독립 검증군으로 설명하지 않는다.

동일 원본의 제외된 검토본도 분석자 간 차이 평가 근거로 보존한다. 대표계수 집계에는 채택본만 사용한다. 통합 프로젝트는 영상 경로를 참조하므로 원본 위치가 바뀌면 해시 검증 후 재연결한다.
