# 포커칩 v5 사용 안내

## 시작하기

이 컴퓨터에 설치된 Python 환경을 연결한 배포본은 `RUN.cmd`를 더블클릭하면 됩니다. 다른 컴퓨터에서는 Python 3.12~3.14를 설치하고 `SETUP.cmd`를 한 번 실행한 다음 `RUN.cmd`를 실행하세요. Python 3.14.6으로 시험했습니다. 소스 배포본이며 독립 실행 EXE는 아닙니다.

1. **새 실험 폴더**에서 결과를 저장할 빈 폴더를 고릅니다. 원본 영상 폴더와 별도로 두세요.
2. 보정 영상이 있다면 **보정 영상 선택**을 누릅니다. 실험 영상 자체의 바둑판 격자도 이용합니다.
3. 실험 영상을 끌어 놓거나 **실험 영상 추가**로 여러 개를 선택합니다. 칩 개수는 자동입니다.
4. **자동 분석 시작**을 누릅니다. 시작·끝을 먼저 클릭할 필요가 없습니다.
5. **저장된 결과**에서 영상별 위치 기록, 회전 계산, 거리 보정, 확인할 장면을 확인합니다. CSV·Excel·그림은 `results`에 자동 저장됩니다.

자동 시작은 ‘지속 이동하는 원판을 충분히 볼 수 있는 시점’의 영상 기반 추정입니다. 고무줄 접촉이 끝났음을 물리적으로 증명한 시각과 같다고 단정하지 않습니다. 자동 구간의 근거와 대체 시작 후보가 `project.json` 및 결과 provenance에 저장됩니다. 계수는 탐색값이며, 연구에 인용하기 전 핵심 구간과 보정을 확인하세요.

## 연구 기본값

| 항목 | 기본값 |
|---|---|
| 저장 영상 / 실제 촬영 | 약 30 fps / 240 fps |
| 실제 시간 | 원본 PTS 재생시간 ÷ 8 |
| 칩 | 검정 몸체, 가장자리 색 표시, 내부 스티커 |
| 질량 / 지름 | 12 g / 40 mm, 설정에서 변경 가능 |
| 관성모멘트 | 균질 원판 `I=mR²/2` 근사 |
| 바둑판 칸 | 짧은 변 22.5 mm, 긴 변 약 23.8889 mm |
| ChArUco | 11×8칸, 한 칸 15 mm, 마커 11 mm, DICT_4X4_50 |
| 롤링셔터 | 보정하지 않음 |

격자 긴 방향 자동 배정은 현재처럼 카메라가 거의 수직인 촬영에 맞춘 가정입니다. 크게 비스듬한 촬영에서는 화면에 더 길게 보이는 방향만으로 실제 긴 방향을 판별할 수 없습니다. 렌즈·줌·해상도가 달라졌다면 보정을 재사용하지 마세요. 칩 두께가 독립 측정되지 않으면 바닥과 칩 윗면의 높이 차이는 미검증 상태입니다.

## 결과를 읽는 법

- `전체_운동데이터.csv`: 모든 완료 영상의 위치·속도·회전 자료. `px`는 **2차원 픽셀 좌표의 단위**입니다. 거리 보정이 있으면 m 좌표도 함께 나옵니다.
- `영상별_요약.xlsx`: 처리 상태, 기록 비율, 결과 위치. 기록 비율은 검출 완전성으로, 위치 정확도 백분율이 아닙니다.
- 영상별 `board_trajectory.jpg`: 실제 바둑판 사진 위에 관측 궤적 표시. 큰 점·격자선도 원본대로 보입니다.
- `board_metric_trajectory.jpg`: 가능한 경우 같은 축척의 평면 복원 사진과 궤적. 보정 가정을 사용한 그림입니다.
- `trajectories.jsonl`, `events.jsonl`, `quality.json`: 자세한 측정값·충돌 상태·검토 이유.
- `확인할_프레임.csv`, `review_intervals.csv`: 흐림, 표식 누락 등 확인할 부분.
- `provenance.json`, run의 `manifest.json`: 원본 해시, 선택 방법, 코드·설정 기록.

빈 값은 0이 아닙니다. 각도 누락이나 충돌 구간을 넘어 각속도를 억지로 이어 붙이지 않습니다. 단일 프레임 방향과 연속 회전각은 다른 열입니다. 원 윤곽의 조건부 피팅 불확실성은 렌즈·배속·높이·모션블러의 모든 오차를 포함하지 않습니다.

## 이상한 장면만 확인하기

**2 이상한 부분 확인**에서 **다음 문제**를 누릅니다. 초록 원은 원 윤곽 측정, 노랑 십자는 가장자리 표식, 파랑 십자는 내부 표식입니다. 주황 원은 낮은 신뢰도입니다. 표식이 없으면 위치가 보여도 회전은 계산되지 않을 수 있습니다.

- **F11 / 영상 전체화면**: 영상 영역 확대. 전체화면에서도 칩 선택·점 지정·충돌 및 정지 지정이 가능합니다.
- **← / →**: 한 프레임, **Shift+← / →**: 열 프레임. 숫자 입력 중에는 입력칸 조작을 우선합니다.
- **오른쪽 드래그**: 이동. 휠 또는 ±: 확대·축소. 오른쪽 더블클릭: 전체 보기.
- **중심 보정 클릭**: 실제 원 중심을 지정합니다. 내부 스티커를 중심으로 지정하는 기능이 아닙니다.
- **가장자리 색 표시 클릭**: 선택 칩의 칠한 한 부분을 찍어 그 장면의 방향을 수정합니다.
- **안쪽 스티커 클릭**: 색 학습용입니다. 중앙에 붙인 스티커 하나만으로 회전 방향을 알 수 없습니다.
- **이 장면에서 수정할 것**: 충돌 전후, 놓친 충돌, 정지·이탈 등을 지정합니다.
- 수정 후 **보정 반영 재분석**을 실행하세요. 이전 run은 보존되고 새 계산 결과가 만들어집니다.

반복 흰 무늬 6개는 절대 회전각 기준이 아닙니다. 반복 무늬만으로는 약 60° 주기의 방향 혼동이 생길 수 있어, 고유한 색 표식이 주 기준입니다.

## 시작·끝을 직접 바꾸고 싶다면

영상 넣기의 **구간 직접 지정 (선택)**에서 시작 장면을 찾고 **현재 장면을 시작으로 고정**합니다. 끝 장면을 찾고 **현재 장면을 종료로 지정**한 뒤 구간을 적용합니다. 끝을 먼저 정해도 됩니다. 다른 장면을 탐색해도 고정한 시작은 변하지 않습니다.

프레임 번호는 **0부터** 시작합니다. 첫 임의 이동 시 프레임 색인 생성으로 잠시 기다릴 수 있습니다. 이후 키프레임부터 읽고 픽셀 체크섬까지 검증합니다. 동일 PTS가 반복되거나 검증이 실패하면 정확성을 위해 순차 읽기로 돌아갑니다. 원본을 변환하거나 덮어쓰지 않습니다.

완전 정지는 이후 위치 기록을 지우지 않고 피팅 사용을 중단합니다. ‘이동만 멈춤’은 회전 정지가 아닙니다. 바닥 이탈과 화면 이탈도 다르게 지정할 수 있습니다.

## 계수 구하기와 고정 계수 검증

저장된 결과 아래에서:

1. **영상 용도 나누기**: 일부 영상을 ‘계수 구하기’, 나머지는 ‘고정 계수 검증’으로 지정합니다.
2. **측정용 영상으로 계수 구하기**: Farkas 자유운동 마찰, 위치 기반 법선 반발, 회전이 포함된 접선 IFR 순으로 계산합니다.
3. **저장 계수로 검증 영상 비교**: 계수는 바꾸지 않고 비교합니다. 자유운동 초기 12개 관측은 초기조건 추정용이며 평가에서 제외합니다.

자동 충돌은 경계 폭·전후 표본·접근 속도 신호·법선 불확실성 기준을 모두 만족할 때만 탐색 피팅에 포함합니다. 사람 확인으로 표시하지 않습니다. 다중 동시접촉, 불명확한 전후 상태, 각속도 누락, 식별 불가능한 접선 계수는 보류하며 이유를 저장합니다. 법선 반발계수는 회전이 없어도 측정할 수 있지만 유효한 위치 전후 상태는 필요합니다.

진행률은 처리 단계와 수치 계산 예산에 따른 %이며 남은 시간의 정확한 예측은 아닙니다. 중단은 안전한 프레임·수치 계산 경계에서 반영됩니다.

같은 원본 파일이나 같은 원본에서 잘라낸 클립을 학습과 검증 양쪽에 사용하지 마세요. 같은 촬영 세션의 영상 분리는 공통 보정 오차를 제거하지 않습니다. 이번 개발에 사용한 영상은 최종 논문의 독립 검증 영상으로 간주하지 마세요.

## 터미널 실행

프로그램 폴더에서 PowerShell을 엽니다. 이미 이 컴퓨터의 런타임을 연결했다면 RUN.cmd가 가장 간단합니다. 별도 가상환경을 만든 경우:

```powershell
.\.venv\Scripts\python.exe -m pokerchip.cli init D:\PokerChipResults\trial01
.\.venv\Scripts\python.exe -m pokerchip.cli add D:\PokerChipResults\trial01 D:\Videos\example.mp4
.\.venv\Scripts\python.exe -m pokerchip.cli auto D:\PokerChipResults\trial01
```

CLI `add`도 개수를 자동 인식합니다. `--chips chip_1 chip_2`처럼 지정하면 수동 참여 목록을 사용합니다. 검증 스크립트 `validation/run_v5_real.py`는 경로 목록 JSON을 받아 GUI와 같은 자동 서비스를 실행합니다.

## 검증 범위

상세 기록은 `validation/test-records/v5/REPORT_KO.md`를 참고하세요. 자동 처리 성공·회귀시험 통과·프레임 읽기의 픽셀 일치는 각각 서로 다른 검증입니다. 그것만으로 원 중심의 실제 mm 오차나 계수의 정확도를 확정할 수 없습니다.
