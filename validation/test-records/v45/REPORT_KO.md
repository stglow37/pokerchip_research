# PokerChip Astra v4.5 인수·검증 보고서

작성: 2026-10-01 / Windows, Python 3.14.6. 원본 `pokerchip_collision_0930`, 기존 v3.5·v4 프로젝트와 실험 영상을 보존하고 별도 v4.5를 제작했다.

## 1. 이번 버전의 결과

v4 개선요구사항의 핵심은 **관측·수정·구간·충돌 승인·계수 피팅이 같은 근거를 사용하게 만드는 것**이다. v4.5에는 다음을 구현했다.

1. 시작 장면을 사람이 선택하는 원칙 유지. 시작 선택과 측정 검토에 전체화면, 프레임 번호 입력, 한 장씩 이동, 휠/버튼 확대, 오른쪽 드래그 이동.
2. 칩별 정지 확인, 화면 이탈 직전, 바닥 이탈, 재진입, 관측/피팅 구간 표. 정지한 칩을 삭제하거나 미래 충돌에서 없애지 않는다.
3. 넓은 충돌 탐색 범위와 유효한 직전·직후 장면 분리. 자동 변화점 제안과 두 화면 수동 비교. 실제 충돌을 피팅에서 제외해도 속도 계산은 충돌을 가로지르지 않는다.
4. 가장자리·안쪽 표식 표시와 상태 설명. 중심 수정 뒤 방향 재계산 또는 무효화. 현재 프레임의 각도 수정과 다음 추적용 색 학습을 분리.
5. 보정된 2차원 x-y 궤적, 위치·회전 그래프. 보정 안 된 경우도 x-y 두 좌표이며 단위만 px임을 표시.
6. 계수별 준비 상태·미산출 이유, 계산 단계·반복 평가 수·경과시간·취소. 영상 분석의 현재 영상 번호/비율. 명확한 체크박스 테두리.
7. 잠정 법선 계수와 IFR 입력 자격을 분리하고, 비식별·경계값·비물리 해를 고정 계수에 혼입하지 않는다. 빈 계수/빈 검증도 이유를 남긴다.
8. 실제 다중 칩에서 발생한 Excel 배열 저장 오류, 수동 평면 보정 덮어쓰기, 다른 프레임의 클릭 적용, 반복 재진입 구간 연결 오류를 해결했다.

세부 대응은 [요구사항 대응표](../../../docs/development/V45_REQUIREMENTS_KO.md), 사용 절차는 [사용설명서](../../../docs/operations/README_V45_KO.md)에 있다.

### 원본과 Drive를 어떻게 연결했는가

사용자 Drive의 현재 목록을 조회하고, 이미 연구 폴더에 있던 로컬 원본을 사용했다. 파일명·Drive 크기·과거 Drive ID별 SHA-256 기록과 실제 로컬 해시를 대조했다. 이번에 모든 영상을 새로 다운로드했다고 주장하지 않는다. 원본 위치는 연구 폴더의 `실제 실험 영상/02_실제 실험 영상`이다.

로컬 검증본의 `drive_inventory.json`, `real_video_diagnostic.csv/json`에 49개 목록, 개수, 상태, 코드 해시와 원본 해시를 기록했다. 이 파일에는 원본 Drive 식별자와 로컬 경로가 있어 공개 Git 저장소에서는 제외한다. 전체 재생 구간 검사에는 별도의 진단용 진입점을 사용했다. 이 진입점은 계수용 역할을 제외로 고정하고 시작 승인 우회를 검사 내부에서만 수행한다. 배포 프로그램의 필수 사람 시작 승인 규칙은 유지된다. 진단 결과를 계수 측정 데이터로 사용하지 않았다.

49개 검사는 개발 중 실행 및 오류 수정 뒤 재실행의 최종 성공 기록이다. 각 실행의 코드 해시를 그대로 남겼으며 모두 마지막 UI 수정 이후 새로 계산했다고 바꾸지 않았다. 마지막 과학 계산 코드로 별도 3개 사람 시작점 재현과 피팅·검증을 다시 실행했다. 출력 기록을 일괄 최신 해시로 위조하지 않는다.

### 발견된 실패와 처리

- 첫 진단의 일부 실패는 시험 스크립트가 `frame=None`을 숫자로 처리한 오류였다. 진단 스크립트를 수정하고 재실행했다.
- 충돌 경계가 배열로 저장된 경우 Excel 셀에 배열을 직접 넣어 실패했다. 구조화 값을 JSON 문자열로 내보내도록 수정하고 실제 영상 및 Excel 재읽기 회귀시험으로 확인했다.
- 재실행 뒤 49개의 최종 소프트웨어 처리 실패는 0개다. 품질 경고·계수 보류는 여전히 유효한 연구 결과이며 ‘실패 0’에 묻어 숨기지 않는다.

## 4. 실제 계수 피팅 재현

기존 TEST1에서 사람이 저장한 시작 선택의 원본 해시가 현재 영상과 같음을 확인했다.

| 용도 | 영상 | 시작 프레임 |
|---|---|---:|
| 계수 측정 | 20260928_200141 | 108 |
| 계수 측정 | 20260928_200214 | 32 |
| 계수 고정 검증 | 20260928_200247 | 110 |

이번에는 기존 사용자 시작 선택을 재현했으며 선택이 실제 해방 시각으로 완벽하다는 새 정답 판정을 하지 않았다. 기존 충돌 전체 승인과 수동 보정은 자동 승계하지 않았다.

공통 Farkas 자유운동 4구간에서 **바닥 마찰계수 μ ≈ 0.33928**이 나왔다. 상태는 잠정이며 확정 물성치가 아니다. 95% 절대 신뢰구간을 새로 산출하거나 연구적으로 인증했다고 주장하지 않는다. 상세 최적화 진단·사용 프레임은 `constants.json`에 있다.

이 값을 고정한 검증 영상의 자유운동 2구간:

| 대상 | 위치 벡터 RMSE | 각도 RMSE |
|---|---:|---:|
| chip_1 | 16.18 mm | 0.0421 rad |
| chip_2 | 6.49 mm | 0.5839 rad |

각 구간 첫 12표본으로 초기 상태를 정한 뒤 나머지를 평가했다. 물리계수는 다시 맞추지 않았다. 이 수치는 영상 관측과 모델 예측 사이의 차이다. 칩 지름이 40 mm이므로 특히 16 mm 오차와 두 번째 칩의 각도 불일치를 “완벽한 일치”로 읽어서는 안 된다. 모델 가정, 시작/구간, 표식·보정 오차의 영향을 구분해 후속 연구로 확인해야 한다. 개발에 반복 사용한 영상이며 같은 세션 보정을 공유하므로 엄밀한 새 독립 검증은 아니다.

법선 반발계수는 이번 재현에서 **검토 승인된 위치 기반 충돌 자료가 없어 보류**했다. 접선 반발·충돌 마찰도 함께 값을 만들지 않았다. 이는 계산 함수 미구현 때문이 아니다. 위치만 있는 법선 추정, 정상적인 합성 물성 복원, 회전 포함 IFR, 식별성 부족과 비물리 해 차단은 자동 시험으로 검사했다. 실제 영상에서는 충돌 전후 장면과 추적을 확인한 뒤 그 사건을 승인해야 한다.

## 5. 이론과 피팅에서 유지한 구분

- Farkas는 균일 접촉 압력·평면 원판 마찰 모델이다. 극한, 독립 면적 적분, 정지, 에너지와 수치 적분을 검산한다. 기존 검산된 지배식을 새 근거 없이 바꾸지 않았다.
- IFR는 원문 제한 분기와 임의 초기 회전을 포함한 접촉 기반 확장 분기를 구분한다. 기본 회전 분기의 실험 타당성을 원문의 검증과 동일시하지 않는다.
- 법선 반발 추정은 위치 기반 입력 자격을 별도로 검사한다. 회전 누락 하나 때문에 위치 기반 결과까지 무조건 지우지 않는다.
- 접선 반발과 충돌 마찰은 여러 조건에서도 서로 구별되지 않을 수 있다. 최적화 성공만으로 두 계수를 허용하지 않는다.
- bootstrap의 단위를 검산하고 물리 허용·식별성 처리를 개선했으나, 기본 간편 피팅 값에 절대 정확도 백분율을 붙이지 않는다. normal_sigma는 단위 법선의 방향각 오차가 아니라 법선 상대속도의 표준편차(m/s)이다.
- 다중 동시 충돌이나 들뜸에는 검증되지 않은 임의 쌍 순서의 해를 넣지 않는다. 해당 사건은 보류 사유를 가진다.

## 6. 설치·사용과 인계

연구 폴더의 새 `시뮬레이션/PokerChip_Astra_v4.5/pokerchip_research`를 사용한다. 이 노트북용 사본에는 이미 검사한 Python 환경 연결을 저장한다. `RUN.cmd`로 열 수 있다. 공유 ZIP은 기기별 경로 연결을 제외하며 다른 PC는 `SETUP.cmd`로 준비한다. Python 없는 PC용 독립 EXE를 제작·검사한 배포본은 아니다.

기존 프로젝트는 복사본으로 열고 재분석한다. 오래된 분석은 ‘설정 변경·다시 분석 필요’로 표시될 수 있다. 과거 수동 승인이 새 측정에 무조건 유효해지는 것이 아니다. 원본 결과를 보존한다.

첫 사용: **새 실험 폴더 → 보정/실험 영상 추가 → 각 영상 시작 장면 확인 → 측정 시작 → 이상한 부분 검토 → 보정 반영 재분석 → 영상 용도 분리 → 계수 측정/고정 검증**. 자세한 버튼 설명은 매뉴얼 참조.

이 릴리스에서 확인한 소프트웨어 오류는 수정·검사했다. 다만 모든 미래 영상과 실제 물리 모델의 완전성을 보장할 수는 없다. v4.5의 기준은 값이 없을 때도 그 이유와 필요한 연구자 조작을 남기고, 관측·파생량·모델·검증을 추적 가능하게 만드는 것이다.
