# 포커칩 v5 개발·실제 영상 검증 보고서

이 보고서는 v5.0.0의 소프트웨어 동작과 실제 영상 개발 검증을 설명한다. 원 중심의 절대 mm 정확도나 물리 계수의 참값 정확도를 인증하는 문서는 아니다. 최신 사용법은 [v5 사용 안내](../../../docs/operations/README_V5_KO.md), 요구사항별 적용 범위는 [요구사항 대응표](../../../docs/development/V5_REQUIREMENTS_KO.md)에 있다.

## 1. 무엇이 달라졌는가

영상 추가 → 자동 시작·끝 제안 → 영상별 격자 거리 변환 → 개수 인식 → 위치·표식 관측 → 운동량 계산 → 파일 저장을 같은 서비스에서 실행한다. 사람이 시작 프레임을 지정하지 않아도 처리한다. 자동 구간을 사람이 승인한 것으로 바꾸지는 않는다.

원 피팅은 잘못된 경계가 섞일 때 consensus 초기값을 구하고, robust 원 거리 적합과 이상점 제거 후 재적합을 수행한다. 원호 점이 네 군데만 있다고 전체 윤곽이 보이는 것으로 계산하던 문제를 각도 구간 점유율로 보완했다. 원근 보정으로 얻은 최종 평면 원을 원본에 되돌려 표시하므로 측정 중심과 표시 원이 다른 모델을 따르지 않게 했다. 표식 밝기 임계값은 검정 몸체의 밝기를 고려한다. 공칭 40 mm는 자동 탐색 범위의 정보이며 독립 측정된 정확한 지름으로 간주하지 않는다.

가림·흐림 후 빠르게 이동한 칩을 고정 거리 게이트가 계속 거부하던 문제, 표식 한 프레임 결측으로 주변 각속도까지 대량 결측되던 문제, 하나의 충돌 후보가 관측 누락 때문에 둘로 갈라지던 문제를 고쳤다. 낮은 품질 측정은 표시하되 정상 관측처럼 미분·피팅에 넣지 않는다.

충돌은 근접 후보 범위와 실제 전후 경계를 구분한다. 위치 연속성을 요구하는 변화점을 사용하고, 같은 칩의 이웃 충돌을 회귀 창에서 제외한다. 실제 C006_195730에서 첫 충돌이 두 번째 속도 창에 섞이는 문제를 발견해 수정했다. 원본 376–390프레임 연락 사진은 `C006_contact_sheet.jpg`이다.

피팅은 Farkas 바닥 마찰, 위치만으로 가능한 법선 반발, 회전 상태를 요구하는 접선 IFR로 나눈다. 법선 속도의 전·후 불확실성을 따로 취급하며, 회전 결측 때문에 법선 반발까지 무조건 버리지 않는다. 동시에 충돌하는 여러 접촉을 순서 임의의 두 물체 충돌로 처리하지 않는다. 조건을 만족하지 않는 계수에는 숫자를 억지로 출력하지 않는다.

Farkas 솔버의 균일 압력·전면 원형 접촉 가정과 기존 적분 검산을 유지했다. IFR 기본 모델은 초기 회전을 포함하는 `contact_consistent_reconstruction` 수학적 확장이다. 이를 원논문이 모든 초기 회전 조건에서 실험 검증한 모델로 설명하지 않는다. 원문 범위 분기는 무초기회전·균질 원판 조건에 제한된다. 채택 식, 인쇄식과 다른 부분, 보존량·에너지 검사는 [모델 결정 문서](../../../docs/methods/MODEL_DECISIONS_KO.md)에 있다. v5에서는 솔버 식 자체보다 관측 상태·충돌 시각·피팅 입력과 불확실성 전달을 수정했다.

## 2. UI와 프레임 조작

- 시작 고정값과 탐색 커서를 분리했다. 시작→끝, 끝→시작, 고정 후 중간 탐색을 시험했다.
- 기본 흐름은 영상 넣기 / 이상한 부분 확인 / 저장된 결과이다. 수정 명령은 메뉴로 모으고 고급 설정을 접었다.
- F11 전체화면에서도 칩·수정 도구·충돌 전후를 선택할 수 있다. 우클릭 드래그로 이동한다.
- 원과 별도로 가장자리·안쪽 표식, 방향선, 회전 상태를 표시한다. 초록 원 하나만으로 각도 성공을 판단하지 않게 했다.
- 체크박스 테두리와 선택 표시를 명시했다. 전체 영상 중 순서, 영상별 %, 전체 %, 계수 단계 진행률을 구분한다.
- 실험 바둑판 사진 위에 궤적을 저장한다. 큰 점 9개는 사진에 보이지만 별도의 자동 거리 기준으로 사용하지 않았다.

Windows Qt offscreen으로 1280×900 창과 전체화면을 렌더하고 실제 프레임 표시를 확인했다. 결과는 `ui_real_*.png`에 있다. 모든 모니터·Windows 배율·그래픽 드라이버 조합에서 확인한 것은 아니다.

## 3. 시험 결과와 시간축

CPython 3.14.6에서 전체 회귀시험 **167개 통과**. 시험 로그는 `tests-final.txt`, 버전·코드 해시는 `build.json`이다. 기본 임시 폴더 접근 권한으로 초기 시험 설정이 실패한 경우에는 작업 폴더를 `--basetemp`로 명시해 다시 실행했다. 오류를 통과로 집계하지 않았다.

원본 PTS와 표시 회전을 유지한다. 사용자 촬영 선언에 따라 재생시간÷8을 실제 시간으로 쓴다. 약 30 fps로 저장된 원본을 30 Hz 실험으로 해석하지 않는다. 실제 카메라 노출시각을 별도의 시계로 검증한 것은 아니며 중복·비독립 프레임은 따로 취급한다. 롤링셔터 보정은 하지 않는다.

실제 C007_204700에서 8개 프레임 요청을 순차 디코딩 정답과 대조해 픽셀·시각이 모두 일치했다. 첫 프레임 약 0.075초, 최초 색인을 동반한 이동 약 23.61초, 이후 시험 이동 약 0.14–0.28초였다. 메모리 영상 캐시는 최대 96 MiB로 제한한다. 색인 이전부터 모든 이동이 이 속도라는 뜻은 아니다. `frame_benchmark.json` 참조.

## 4. 보정 검증을 어떻게 해석해야 하는가

9월 28일 C003 별도 ChArUco 영상에서 60개 서로 다른 시점을 사용했다. 렌즈 재투영 RMS는 학습 약 0.294 px, 보류 시점 약 0.424 px였다. 이 숫자는 포커칩 중심의 실측 정확도가 아니다. 바닥에 놓았다는 확인을 주지 않은 시험에서는 평면 H를 임의로 확정하지 않고 pending으로 남겼다. 11개 실험의 거리 변환은 각 실험 영상 격자에 기반한 잠정 보정을 따로 사용한다.

격자 짧은 변 22.5 mm, 긴 변 약 23.8889 mm는 사용자 실측 선언이다. 크게 기울어진 영상에서는 화면에 긴 축이 실제로 긴 칸 방향인지 영상만으로 확정할 수 없다. 실측 방향, 렌즈 변화, 칩 윗면 높이 오차는 별도 확인 대상이다. 재투영 오차나 보정 내부 잔차가 작아도 이 공통 오차는 남을 수 있다.

## 5. C007 빨간 고무줄 검토

자동 시작은 120프레임이었다. 원본 112–117프레임을 확대해 보았을 때 113–116에 분리 전환이 있고 116에서는 분리가 분명하다. 가림·흐림 때문에 정확한 마지막 접촉을 단일 프레임으로 확정하지 않았다. 자동 시작은 이 전환 범위보다 약 4–7프레임, 240 Hz 기준 약 17–29 ms 늦다.

`C007_release_zoom.jpg`, `release_visual_check.json`에 근거를 보존했다. 한 개발자의 영상 확인이므로 독립 다중 작업자 정답이나 전체 검출 정확도는 아니다. 빨간 고무줄을 전용 분할·접촉 해제 검출기로 자동 인식하는 기능까지 구현된 것은 아니다. 현재 자동 시작은 외력이 사라진 참시각보다, 원판을 안정적으로 관측할 수 있는 시점의 제안이다.

### 계수와 검증 오차에 대한 해석

같은 최종 코드로 C004의 1개 칩 영상 2개만 다시 피팅하면 μ_b=0.188653이다. C005까지 포함한 4개 영상/6개 자유운동 구간에서는 μ_b=0.258665로 달라진다. `sensitivity_summary.json`에 두 입력 집합을 기록했다. 따라서 0.258665를 바닥의 확정된 참 마찰계수로 결론 내릴 수 없다.

고정 계수 자유운동 오차도 약 0.085–42.656 mm로 넓다. C007_204700의 긴 구간은 24.801 mm, 이전 C002의 chip_2는 42.656 mm다. 작은 오차의 짧은 구간·정지에 가까운 구간과 긴 이동 구간을 동등한 정확도 증거로 보지 않는다. 전체를 하나의 “정확도 %”로 요약하지 않았다.

가능한 원인은 바닥 위치·칩별 접촉 차이, 균일 압력/관성 근사의 불일치, 각도 계측·높이·거리 보정의 공통 오차, 초기 상태 오차이다. 현재 검증은 이 원인들을 분리해 확정하지 못했다. 모델을 잘 맞추기 위해 관측 위치를 수정하거나 검증 영상을 다시 피팅하지 않았다. 법선 반발도 두 측정 충돌에서는 약 0.75로 비슷하지만 다른 충돌 관측 비는 약 0.48–0.90로 달라, 모든 충돌에 하나의 상수가 충분하다는 결론은 아직 이르다.

실무적으로는 v5의 관측·검토 결과를 확보한 뒤, 바닥 위치와 칩을 고정한 반복실험에서 상수의 안정성을 먼저 확인해야 한다. 숫자가 출력되었다는 사실과 연구에서 그 상수를 채택할 근거가 충분하다는 판단은 구분한다.

## 7. 아직 보장하지 않는 것

자동 완전 정지·화면 이탈·재진입·외력 해제의 모든 조합을 확정하는 상태기계, 반복 인쇄 여섯 부분의 전용 검출기, 큰 점 9개를 기준으로 한 추가 자동 보정은 이번 버전에 포함하지 않았다. 수동 종료/이탈·정지 보정과 검토 기능은 유지한다. 노출 중 섞인 충돌, 심한 흐림·겹침, 표식 해상도 부족은 여전히 관측을 제한한다.

위치·각도 독립 라벨이 없는 상황에서 ‘정확도 99%’와 같은 값을 만들지 않았다. 계수 오차에는 공통 길이·시각 보정, 바닥 접촉 압력 분포, 재질·위치 변화, 칩 관성 근사의 영향도 있다. 출력 covariance는 조건부 값이고 모든 물리 오차를 포함하는 신뢰구간이 아니다.

다음 연구 검증은 개발에 쓰지 않은 영상을 별도 세션에서 확보하고, 중심·표식·해제·충돌 시각을 두 사람이 독립 표시하여 mm/rad/프레임 오차를 측정하는 것이다. 현재 영상의 피팅 오차를 줄이는 것만으로 알고리즘의 독립 정확도를 높였다고 결론 내리지 않는다.

## 8. 배포본 확인

연구 폴더의 `시뮬레이션/PokerChip_Astra_v5`에 소스 실행 배포본을 만들었다. `RUN.cmd`는 새 분석, `RUN_검증예제.cmd`는 이번 11개 실험 결과를 연다. 이 컴퓨터의 기존 Python 3.14 환경을 연결했으며 다른 컴퓨터에는 `SETUP.cmd`를 제공한다. 독립 실행 EXE 배포는 아니다.

배포 폴더 자체에서 v5 모듈을 import하여 버전을 확인하고 실제 `run_gui.py` 진입점을 Qt 이벤트 루프로 열고 닫았다. 복사한 원본 11개의 SHA-256, 각 결과의 최신 분석·내보내기 fingerprint, 집계표 11개 완료 상태, 계수 은행 해시, 학습/검증 원본 중복 없음을 모두 확인했다. `deployment_check.json`에 기록했다. 기존 v4.5 폴더와 사용자 원본 실험 결과는 변경하지 않았다.
